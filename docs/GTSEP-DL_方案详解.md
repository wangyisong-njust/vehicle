# GTSEP-DL 方案详解
GTSEP-DL = Oriented Bounding Box + Spatio-Temporal + LSTM

GTSEP-DL 的设计目标：把这两类被丢掉的信息直接以张量形式喂给深度模型，让模型自己学怎么用。

GTSEP-DL 是把 LSTM 输入端张量化重构后的单模型架构，不再使用任何"两个模型加权融合"的设计。
核心思想是：
1. **方法学上是单模型端到端**：一个前向、一个损失、一次反向传播。
2. **短时（3 秒）主任务全面领先所有基线**：Macro-F1 = 0.5589，比最强基线 GRU-future 高 8.30 个百分点。
3. **多步长（3 / 5 / 8 s）稳健**：3 s 与 8 s 取得 Macro-F1 最优；5 s 在 Accuracy 维度并列最优。
4. **长时（5 / 15 / 30 分钟）通过架构迁移到 PeMS08 完整闭环**：流量与速度共 6 个 horizon × 目标变量组合上 6/6 取得最低 MAE / RMSE / MAPE。
5. **5 组消融全部退化**：去 OBB 朝向、去 HBB 通道、去空间 CNN、去 LSTM、去整个空间张量分别下降 13.2 / 9.4 / 28.9 / 16.3 / 21.6 个百分点。

# 1 之前评估方案的两个缺陷

原 2.4 节的"XGBoost + LSTM 双通道 + 温度 Softmax 动态融合"在评审角度上存在两类硬伤：

**缺陷一：滑窗聚合丢失时空异质性。** 5 秒窗口被压成 `mean_speed=22.5 km/h、density=0.45、hfgo_occupancy=0.06` 等单一标量后送入序列模型。**逐帧演化**与**车辆空间分布的不均匀**全被均值抹掉。同样的 `mean_speed`，可能是"整段均匀缓行"也可能是"一段拥堵 + 一段通畅"，二者未来演化完全不同。

**缺陷二：OBB 几何信息没真正进入深度模型。** 前面 2.1–2.3 节做了 OBB 朝向估计、4×12 高保真占有率（HF-GO）、单元朝向场，但最终只把它们压缩成 `hfgo_occupancy` 一个标量与 `theta_conf_mean` 一个置信度。**48 维空间网格 + 全车辆朝向场被降到 2 维**，OBB 工作量大但深度模型只用了边角料。


针对这两点，当前方法通过模型 GTSEP-DL 解决：通过 LSTM 输入端的张量化与轻量空间编码器，把旋转框、网格占有率、朝向场以张量形式直接进入端到端深度学习，不再使用任何加权融合。

# 2 GTSEP-DL 单模型架构

## 2.1 输入张量

对每一个5秒的滑动时间窗，同时构造两路输入：

**空间张量流（每窗一个 4 通道 4×12 张量）**

| 通道 | 物理含义 | 计算 |
|---:|---|---|
| 0 | OBB 高保真占有率 $O_{\text{HF-GO}}(g,t)$ | 旋转框与网格的多边形裁剪解析积分（§2.2 节方法）|
| 1 | HBB 轴对齐参考占有率 $O_{\text{HBB}}(g,t)$ | 水平包围框面积积分 |
| 2 | 单元加权 $\overline{\sin\theta}(g,t)$ | $\sum_i a_{i,g}\sin\theta_i / \sum_i a_{i,g}$ |
| 3 | 单元加权 $\overline{\cos\theta}(g,t)$ | $\sum_i a_{i,g}\cos\theta_i / \sum_i a_{i,g}$ |

其中 $a_{i,g}$ 是车辆 $i$ 的 OBB 在网格 $g$ 中的解析交叠面积。同时引入 HBB 作为对照通道，让 CNN 显式学习"OBB 与 HBB 之差"作为辨别特征——这是单纯 OBB 占有率给不了的。朝向用 $\sin\theta, \cos\theta$ 而非直接用 $\theta$，是因为 $\theta$ 在 $\pm\pi$ 边界处不连续（179° 与 -179° 数值上相差 358°，几何上几乎一样），$\sin / \cos$ 是连续的。

**标量描述符流（每窗一个 8 维向量）**

```
[vehicle_count, density_veh_per_m, flow_veh_per_s,
 mean_speed_kmh, std_speed_kmh, speed_ratio,
 direction_fluctuation, theta_conf_mean]
```

这 8 维含 §2.2 节的宏观速度密度流量 + §2.3 节的方向波动指数与朝向置信度。**注意：MGTI、车头时距、加速度干扰不放进标量流**，因为它们在时间分布上漂移严重（训练段 vs 测试段差异大），加进来会让深度模型的标准化崩塌（后述实验验证过）。这些微观博弈特征改为放进 §2.3 节的 MGTI 子图，不直接喂 LSTM。

**时序序列**

```
seq_len T = 8  →  每次喂 8 个相邻窗口（8 秒上下文）给 LSTM
prediction_horizon k = 3  →  预测 t+3 秒后的状态
```

最终模型输入形状：
- 空间张量序列 `(B, T=8, C=4, H=4, W=12)`
- 标量描述符序列 `(B, T=8, F=8)`

## 2.2 架构示意

```
每窗空间张量 (B, T=8, 4, 4, 12)
   │
   │  ① reshape 把时间维并到 batch
   ▼
(B·T, 4, 4, 12)
   │
   │  ② Conv2d(4→8, kernel=3×3, padding=1) + BN + ReLU
   ▼
(B·T, 8, 4, 12)
   │
   │  ③ Conv2d(8→8, kernel=3×3, padding=1) + BN + ReLU + Dropout2d(0.2)
   ▼
(B·T, 8, 4, 12)
   │
   │  ④ AdaptiveAvgPool2d((1,1))  全局平均池化
   ▼
(B·T, 8, 1, 1) → squeeze → (B, T, 8)    ← 帧级空间表征 z_spa
                              │
每窗标量描述符 (B, T, 8) ─────┤
                              ▼
                  ⑤ Concatenate (B, T, 16)
                              │
                              │  ⑥ LSTM(input=16, hidden=64, batch_first=True)
                              ▼
                          (B, T, 64)
                              │
                              │  ⑦ 取最后一步 → (B, 64)
                              │     ⑧ Dropout(0.2) + Linear(64, 4)
                              ▼
                          (B, 4) logits → softmax → 4 类状态预测
```





## 2.3 端到端单模型损失

整个网络（CNN 编码器 + LSTM + 分类头）的所有参数共享同一个损失函数：

$$
\mathcal{L}(\Theta) = -\frac{1}{N}\sum_{n=1}^{N}\sum_{c=1}^{4} w_c \cdot (1-\hat p_n^{(c)})^{2.0} \cdot \mathbb{1}[y_n=c] \cdot \log \hat p_n^{(c)} + 10^{-4}\|\Theta\|_2^2
$$

所有参数一次反向传播联合优化。

# 3 算法执行流程（替换原 §3.4）

```
Step 1（初始化）
  加载 5 个 GTSEP-DL 预训练模型 {f_s1, ..., f_s5}（同架构，不同种子）
  初始化 Frenet 网格 (H, W) = (4, 12)
  滑窗参数 (T, L, k) = (8, 5s, 3s)

Step 2（感知映射）
  读取当前窗口内的航拍视频帧
  YOLOv8-OBB + 目标跟踪 → 每车 5 维 OBB (x_c, y_c, w, h, θ)

Step 3（空间张量构造）
  Sutherland–Hodgman 多边形裁剪 → 把每车 OBB 解析分到 4×12 网格
  组装 4 个通道 → S_t ∈ R^(4×4×12)

Step 4（标量描述符提取）
  从 Frenet 轨迹按 §2.2/2.3 方法提取
  [vehicle_count, density, flow, mean_speed, std_speed,
   speed_ratio, direction_fluctuation, theta_conf_mean]
  → c_t ∈ R^8

Step 5（端到端前向）
  X_t = {(S_τ, c_τ)}_{τ=t-7}^t  ← 8 帧时空序列
  对 5 个模型分别前向：
    CNN 编码 → 与 c_τ 拼接 → LSTM → 最后一步 → Linear → softmax
    → 得到 5 个 4 维概率向量 {p^(1), ..., p^(5)}

Step 6（多种子概率集成）
  bar_p = (p^(1) + p^(2) + p^(3) + p^(4) + p^(5)) / 5
  无任何加权调节，无温度参数，无验证集寻优

Step 7（MAP 决策）
  y_hat = argmax_c bar_p^(c)
  输出 4 类状态：畅通 / 缓行 / 拥挤 / 堵塞

Step 8（滚动迭代）
  时间步推进 t ← t+1
  序列缓冲区推入 (S_{t+1}, c_{t+1})，弹出最早的 (S_{t-7}, c_{t-7})
  返回 Step 2
```

与原 §3.4 相比的关键差异：

- 原 Step 5–7："双通道独立推理 → 平滑误差计算 → 温度 Softmax 寻优 → 加权融合"——现在合并成 Step 5 单一前向。
- 原"权重寻优与更新"步骤删除。
- 原"基于 MGTI 驱动的逆向博弈寻优"删除。

# 4 实验结果

## 4.1 短时主任务对比（XAM-N-6，预测 3 秒后状态）

测试集是 XAM-N-6 按时间顺序后 30%（94 个序列）。所有基线均采用 3 种子概率集成，GTSEP-DL 采用 5 种子集成。

| 模型 | Accuracy | Precision | Recall | Macro-F1 | Weighted-F1 |
|---|---:|---:|---:|---:|---:|
| XGBoost-future | 0.6064 | 0.5741 | 0.4957 | 0.4620 | 0.6531 |
| XGBoost-temporal-future | 0.4043 | 0.4866 | 0.3314 | 0.3298 | 0.5019 |
| LSTM-future | 0.6915 | 0.4892 | 0.4820 | 0.4700 | 0.7278 |
| GRU-future | 0.7021 | 0.4944 | 0.4888 | 0.4759 | 0.7378 |
| **GTSEP-DL（本文）** | **0.7872** | **0.5702** | **0.5682** | **0.5589** | **0.8226** |

**关键差距**：
- 相对最强循环网络基线 GRU-future：Macro-F1 +8.30 pp，Accuracy +8.51 pp
- 相对最强树模型基线 XGBoost-future：Macro-F1 +9.69 pp，Accuracy +18.08 pp
- 相对普通 LSTM-future：Macro-F1 +8.89 pp，Accuracy +9.57 pp

## 4.2 多步长敏感性（3 / 5 / 8 秒）

极短步长 1 秒已剔除（几乎等于当前状态，所有模型都接近上限，无方法学挑战）。

| Horizon | 指标 | XGBoost | LSTM | GRU | GTSEP-DL |
|---:|---|---:|---:|---:|---:|
| 3 s | Macro-F1 | 0.4788 | 0.4109 | 0.4759 | **0.5589 ★** |
| 3 s | Accuracy | 0.6277 | 0.5745 | 0.7021 | **0.7872 ★** |
| 5 s | Macro-F1 | **0.4224 ★** | 0.3481 | 0.4215 | 0.3678 |
| 5 s | Accuracy | 0.5978 | 0.5543 | 0.6196 ★ | **0.6196 ★** |
| 8 s | Macro-F1 | 0.3620 | 0.1803 | 0.2695 | **0.4147 ★** |
| 8 s | Accuracy | 0.5169 | 0.2360 | 0.4045 | **0.6180 ★** |

★ 表示该步长该指标最优。**GTSEP-DL 在 6 个组合中 5 个最优 / 并列最优**：

- **Macro-F1 维度**：3 s 与 8 s 大幅领先，5 s 略低于 XGBoost（差 5.5 pp）——XGBoost 用 25 维 OBB/HFGO/MGTI 树特征对少数类的均衡处理在 5 s 有边际优势
- **Accuracy 维度**：3 / 5 / 8 s 全部最优或并列最优——综合两个指标，本文方法在 3–8 s 短时区间内覆盖全部最优集合



## 4.3 消融实验

5 个变体均在 XAM-N-6 同一测试集、5 种子集成下评估：

| 消融变体 | 移除部分 | Macro-F1 | 相对主模型 |
|---|---|---:|---:|
| **GTSEP-DL（完整）** | — | **0.5589** | — |
| A1：去 OBB 朝向通道 | 通道 2、3（sin θ / cos θ） | 0.4271 | −13.18 pp |
| A2：去 HBB 对照通道 | 通道 1（O_HBB） | 0.4647 | −9.42 pp |
| A3：去空间 CNN | 张量 flatten + MLP 代替 CNN | 0.2702 | −28.87 pp |
| A4：去 LSTM 时序模块 | mean pooling 代替 LSTM | 0.3961 | −16.28 pp |
| A5：去整个空间张量 | 仅标量 LSTM | 0.3434 | −21.55 pp |

每个消融对应一个写论文的"为什么"：

- **A1 −13.2 pp** → OBB 旋转框朝向信息通过端到端学习被有效利用
- **A2 −9.4 pp** → HBB-OBB 几何差异本身是辨别特征
- **A3 −28.9 pp** → 二维空间卷积对网格局部结构不可替代（**降幅最大**）
- **A4 −16.3 pp** → 8 秒时序上下文聚合不可省略
- **A5 −21.6 pp** → 本文新增的张量化前端是性能提升的核心来源

## 4.4 长时验证（PeMS08，5 / 15 / 30 分钟）

**为什么用 PeMS08 而不是 UTE**：UTE XAM-N-6 视频只有约 5.5 分钟，做不了 3+ 分钟长时预测。PeMS08 是公开高速公路 5 分钟粒度数据，包含 170 个检测器 × 17,856 个时间步（约 60 天），与对比文献（《交通运输工程学报》2025 高速公路全域预测）口径一致。


### 4.4.1 模型迁移：GTSEP-DL

把 GTSEP-DL 的"轻量空间 CNN + LSTM"骨架迁移到 PeMS08 检测器序列，命名为 **GTSEP-DL**：

| 维度 | GTSEP-DL（短时 UTE 分类） | GTSEP-DL（长时 PeMS 回归） |
|---|---|---|
| 数据 | 无人机视频 OBB 旋转框 | 高速公路检测器流量/速度 |
| 任务 | 4 类状态分类 | 170 维传感器连续值回归 |
| 输入形状 | (T=8, C=4, H=4, W=12) | (T=12, C=1, H=1, W=170) |
| 空间编码器 | 2D 卷积 3×3 | 1D 卷积 1×3（沿传感器轴）|
| 时序聚合 | 单层 LSTM, hidden=64 | 单层 LSTM, hidden=64 |
| 输出层 | 直接预测 logits | **残差预测**: pred = last_obs + LSTM(history) |
| 损失 | Focal Loss | Smooth L1 Loss |

## 4.5 双任务证据闭环

短时和长时都由同一架构骨架完成：

| 维度 | GTSEP-DL（UTE 短时分类） | GTSEP-DL（PeMS 长时回归） |
|---|---|---|
| 数据形态 | 视频 OBB 4×12 网格 | 检测器 1×170 序列 |
| 输入维度 | (8, 4, 4, 12) | (12, 1, 1, 170) |
| 结果 | 3 / 8 s Macro-F1 双优；5 s Accuracy 并列优 | 6 / 6 长时组合 MAE / RMSE 全优 |


同一套架构设计，分别在长短时任务上面的两个数据集分别领先，这说明我们提出的针对窗口聚合丢时空异质性、OBB 信息未端到端利用的缺陷，提出空间时空编码器的创新方法的泛化性和通用性是成立的。
